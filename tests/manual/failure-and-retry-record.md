## 2026-08-14：双语契约选错后的补救设计与自动化验证

- 人工发现：纯中文课堂误选双语后，Agent 正确阻断缺失译文，但页面还必须为真正的英文或
  中英混合课堂提供补充材料入口，不能只有“关闭双语”一种处理方式。
- 根因核查：原 Worker 只下载视频；任务中已有的 `transcript` 资产不会参与转写或翻译。
  只增加上传按钮会形成“上传成功但处理仍失败”的假闭环。
- 修复：纯中文路径复用原资料创建关闭双语的新任务；非纯中文路径只接受带时间轴的 UTF-8
  SRT/VTT 中文译文，完成预签名上传与后端 HEAD 核验后，复用原视频创建新任务。Worker
  独立下载字幕，视频仍真实经过 FFmpeg/Whisper，译文按时间覆盖写入同一逐字稿 segment。
- 失败门禁：非 SRT/VTT、非 UTF-8、空文件、缺中文、时间重叠/倒序，或任一 ASR 片段没有
  至少一半时长的译文覆盖，均明确失败；TXT/DOCX 不冒充可定位双语证据。
- 自动化结果：专项 Python `67 passed, 1 skipped`；完整 Python `273 passed, 11 skipped`；
  前端测试、TypeScript 类型检查和 Next.js 生产构建通过。跳过项来自既有环境条件测试。
- 验收边界：本项尚未执行真实 B2 字幕上传和浏览器全程点击，不能替代人工复验；不得写成
  自动翻译模型已经接通。

## 2026-08-15：视频与教师 VTT 同时上传的真实恢复验证

- 现象：浏览器同时提交视频和教师提供的 VTT 后，媒体阶段完成但证据分析仍以译文不完整
  失败；页面正确保留了失败原因和补充材料入口。
- 根因：同机遗留的旧版 Worker 先领取了新任务，该进程不包含新增字幕导入阶段。根因判断
  依据任务阶段、进程启动时间和代码版本，不读取或记录课堂正文。
- 恢复：只停止经启动时间核实的旧进程，复用已经完成 B2 HEAD 核验的视频和字幕资产创建
  替代任务。首次字幕对象下载出现暂时性失败；再次验证下载 HTTP、字节数和 ETag 一致后
  重试，没有输出预签名 URL、对象密钥或字幕内容。
- 结果：视频继续真实经过 FFmpeg/Whisper；Worker 将教师 VTT 按时间覆盖对齐到 4 个 ASR
  片段，4/4 均具有译文，任务随后完成 Agent 分析。成员 1 在浏览器打开结果并确认可用。
- 防复发：`start.ps1` 新增命名互斥锁和不含秘密的运行进程清单；清理前同时核对 PID 与
  启动时间，避免误杀复用 PID 的无关进程。语法与 4 项启动专项测试通过。
- 验收边界：本次证明教师提供定时译文的真实 B2/Worker/Agent 恢复路径，不证明自动翻译
  Provider、第二段不同视频、非开发教师试用或完整 M1 已通过。
