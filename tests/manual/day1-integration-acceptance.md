## 3. 阻塞项与责任边界

1. **成员 3：先冻结跨模块契约。** 至少明确课堂、资源、预签名上传、上传确认、处理任务和报告的请求、响应、错误与状态枚举，再实现 M1 所需最小 API。
2. **成员 4：实现最小视频处理链。** 对一个非预置真实视频完成对象读取、FFmpeg 音频抽取、带时间戳 ASR、双语处理和证据索引，并回写真实阶段状态。
3. **成员 5：实现最小 Agent 与质量链。** 读取证据、输出结构化事实/判断/建议、拒绝无证据结论，并保证报告只接收 accepted/modified 内容。
4. **成员 2：实现证据工作台。** 使用冻结 Schema 展示播放器、时间轴、逐字稿、课件证据和人工接受/修改/驳回状态。
5. **成员 1：不替代上述模块。** 在 Schema 冻结后接入真实课堂、上传、任务和报告接口；在此之前继续保持“服务未接通”的诚实状态。

## 4. 本次发现的问题

- **问题：** 原型页面已经可以完成较长的交互流程，容易让人误以为后端上传和 Agent 已经接通。
- **原因：** 阶段 0 创建了完整目录和页面骨架，但后端、Worker、Agent 仍只有 TODO；此前 CI 也只检查骨架和敏感文件。
- **本次修改：** 上传入口明确禁用真实上传；PR #8 新增前端测试、类型检查和生产构建 CI。
- **当前限制：** CI 只能证明前端可构建和既有契约没有回退，不能证明真实视频处理、证据定位或报告闭环已经可用。

## 5. 复验入口条件

以下条件全部满足后再进行第二次集成验收：

- `interface-contracts.md` 已由成员 3 更新并由成员 1、2、4、5确认。
- 后端提供可运行健康检查及 M1 最小课堂、上传、任务、复核和报告接口。
- 使用一个非预置视频能产生新的任务 ID、真实阶段状态和带时间戳逐字稿。
- Agent 只基于该任务证据生成结构化结论，并为每条结论返回可定位引用。
- 前端能展示失败原因和重试入口，且更换输入后不会复用旧结果。
- 只有教师接受或修改确认的结论可以进入报告。
