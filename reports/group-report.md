## 1. 问题、用户与产品定位

项目背景是华五某高校与网易联合探索 AI 版中国大学 MOOC。目标用户是需要复盘一节课堂并
形成改进方案的高校教师。教师面对长视频、逐字稿和课件时，难以快速定位关键片段，也难以核对
AI 判断依据了哪段原话或画面。

产品因此聚焦一个闭环：教师说明复盘目标，上传真实课堂资料，系统生成可定位的逐字稿与教学
分析，教师逐条接受、修改或驳回，最后只把人工确认内容组合成报告。系统不替学校自动评分，
无证据结论不得进入最终报告。

## 2. 产品方案与交互

核心流程是：

```text
创建课程/课堂 → 对话确认分析契约 → 上传视频及可选资料 → 查看真实处理状态
→ 校订逐字稿/译文 → 核对事实、判断和建议及其证据 → 人工复核 → 报告编辑与导出
```

对话区负责明确目标与解释结果，工作区负责视频、时间轴、逐字稿、课件和结论操作。证据工作台
一次聚焦一条结论，显示总数、当前项与未完成数；保存后自动进入下一条未复核内容。所有结论
复核完成前，报告入口保持禁用。

在单节课堂 M1 闭环之上，成员 1 后续实现 M2/M3：把教师确认建议转换为带成功标准的改进行动，
关联同课程第二轮课堂，生成带两轮证据与 Trace 的候选对比并再次交由教师确认；再按课程汇总课堂、
任务、复核和报告状态。汇总报告只采用真实轮次中教师确认的内容，不把合成机制验证写成教学成效。

前端采用“雾境竹影”基线：霞鹜文楷与 Fraunces、雾面玻璃、克制的竹影和微交互。设计优先
尊重高校教师的阅读习惯，正文与标签不使用过小字号，状态色保持一致并提供清晰键盘焦点。

## 3. 技术实现

### 3.1 前端与后端

Next.js 前端通过同源 BFF 与 FastAPI 通信，短期 JWT 保存在 HttpOnly Cookie。后端使用
PostgreSQL 记录用户、课程、课堂、资产、任务、逐字稿、结论、复核历史、报告与审计；视频
本体保存在私有 S3 兼容对象存储。上传完成后由后端 HEAD 校验对象存在、大小和类型。

### 3.2 Worker 与证据

Worker 领取带租约任务，通过限时 URL 下载视频，完成 FFmpeg 音频抽取、Whisper 识别和时间戳
逐字稿写回。英文或混合片段由 loopback-only 的 Ollama Provider 逐句翻译，结构、顺序和中文
覆盖不合格时失败关闭。教师也可补充 UTF-8 SRT/VTT；系统仍从视频生成 ASR 原文，再按时间范围
对齐译文，并优先采用教师输入。成员 1 后续补齐了课件下载、页级解析、PostgreSQL 写回、
账号隔离、Agent 引用和前端原页定位；又依据获授权公开视频画面与 ASR 人工重建 8 页可编辑
课件，完成真实 B2、Worker、PostgreSQL 与 Agent 技术 E2E：8/8 页入库，生成 3 条结论且
3/3 含课件原页引用。重建课件在标题页和文档中均标注来源边界，不冒充授课教师原始课件；
获授权原始课堂课件的浏览器人工验收尚未完成。

### 3.3 Agent 与报告

Agent 使用显式状态机、有界工具和证据校验门禁，而不是无限循环的自由 ReAct。当前真实模型
Provider 是本地 Ollama `qwen3.5:4b`。输出经 JSON Schema、类型枚举和证据时间范围校验后
写回；教师复核历史可追溯，报告只接收 `accepted` 或 `modified` 内容。服务端支持 Markdown、
HTML 和 PDF 导出。

### 3.4 可观测性与安全

任务、Worker 和 Agent 使用 `trace_id`、阶段状态、租约、心跳、重试和审计事件回溯。Worker
与 Agent 使用不同服务令牌。长期对象存储密钥、数据库密码、Cookie、预签名 URL 和模型隐藏
推理不进入前端、日志、报告或 Git。所有业务资源都由后端校验账号归属。

## 4. 验证、完成范围与限制

两段内容不同的真实课程视频（计算机/人工智能、人文社科各一段）均已完成：

```text
B2 上传 → HEAD 核验 → Worker → FFmpeg → Whisper → PostgreSQL 时间戳逐字稿
→ Ollama 分析 → 教师接受/修改/驳回 → Markdown/HTML/PDF
```

浏览器还完成了视频与教师 VTT 同时上传、重新 ASR、时间对齐和 Agent 分析。自动翻译 Provider
先以合成输入验证英文、混合文本和提示注入边界，随后以真实英文课堂完成自动逐句翻译与 Agent
分析 E2E：46 条原始 ASR 中剔除 1 条静音尾部重复字符幻觉，45/45 有效片段有译文并生成 3 条
结论。自动化覆盖 Python、前端契约、类型检查、生产构建、权限和安全边界；详细命令、失败恢复及
最新重跑规则见测试总记录。

当前可声明“双输入真实数据技术 E2E、真实英文课堂自动翻译 E2E 与重建课件证据技术 E2E 已通过”，但不能声明完整 M1 已完成。
两段媒体的来源 URL 与复用授权记录仍待补齐；其余门禁包括获授权原始课堂课件的浏览器人工验收、非开发教师独立试用、
同场景修改复测和干净环境正式部署复现。

## 5. AI 协作

团队使用 AI 参与需求梳理、架构比较、UI 设计、代码、测试、故障定位和文档整理。人工保留了
最终判断权，并重点纠正了以下类型的问题：

- 把阶段 0 骨架或 Mock 描述成真实功能；
- 在双语证据缺失时继续生成分析；
- 旧 Worker 进程消费新契约任务；
- 上传、任务、报告页面在刷新或会话过期后丢失状态；
- 按计划角色或文件路径错误归属实际贡献；
- 把开发者操作扩大为真实用户验收。

AI 产出通过代码审查、自动化、真实输入、数据库记录、浏览器操作和 Git/PR 历史核验；被修改或
推翻的原因保留在提交、PR 和测试记录中。

## 6. 贡献审计口径

### 6.1 定义

- **实际完成：** 已合并到 `main`，并有测试、CI 或人工验证支持。
- **共同完成：** 原作者实现后由其他成员修复或补齐；分别记录原实现和后续工作。
- **尝试：** 成员分支存在提交但未通过 PR 合入，不计作最终交付。
- **计划责任：** 说明预期分工，不能替代实际贡献证据。

PR 数量只用于定位证据，不直接代表工作量、质量或最终个人评分。提交作者、PR 作者、审查者和
后续修复者可能不同，必须结合提交内容判断。

## 12. 结论与后续计划

项目已经从阶段 0 骨架发展为一条可运行、可回溯、具有人在回路的真实技术纵向链路。最重要的
