## 2. 背景、用户与边界

### 2.1 任务背景

项目背景是华五某高校与网易联合探索 AI 版中国大学 MOOC。产品聚焦公开课建设中的课后复盘，
不是通用 AI 功能集合，也不是教学绩效评分系统。

首批用户是需要复盘一节课堂并形成改进方案的高校教师。课程团队和教学管理者可以阅读或协作，
但 M1 不为他们另建一套流程。

### 2.2 用户问题

教师面对几十分钟的视频、逐字稿和课件时，通常难以：

- 快速定位值得复盘的片段；
- 核对一条教学判断依据了哪段原话或画面；
- 在 AI 建议与教师专业判断之间保留清晰边界；
- 把确认后的内容整理成可追溯报告。

因此系统的核心任务是：**把课堂资料转化为可定位证据、可人工复核、可追溯导出的教学分析。**

### 2.3 使用边界

- 系统辅助教师复盘，不替学校自动给教师打分。
- 无原文或画面证据的判断不能进入最终报告。
- 教师拥有最终决定权；待复核和已驳回内容不得进入报告。
- M1 只覆盖单节课堂闭环；M2 的二次改进对比、M3 的多课程管理和知识图谱均为后续可选项。
- 公开演示只使用有权处理、来源与许可可追溯的资料；私密课堂须另行取得授权并做隐私评估。

## 3. 需求基线与当前完成度

### 3.1 M1 必须实现

1. 教师通过自然语言说明复盘目标，Agent 只追问必要范围、重点和判断条件，教师确认后处理。
2. 网页可上传真实课堂视频，并可补充课件、逐字稿或带时间轴译文；逐字稿不能替代视频处理链路。
3. 视频持久保存到对象存储，数据库保存对象地址、归属、状态和业务记录，不直接保存视频二进制。
4. 页面展示上传、音频抽取、媒体分段、语音识别、双语对齐、课件解析、证据索引和分析的真实状态；失败可解释并可恢复。
5. 系统生成带时间点和说话人的逐字稿；英文或中英混合课堂同时保留英文原文和逐句中文译文。
6. 教师可修改逐字稿、说话人和译文。
7. 分析严格区分事实、判断和建议；每条结论连接视频时间、原文、课件页或画面证据。
8. 教师可接受、修改确认或驳回结论，并保留内容版本、复核说明和状态。
9. 所有结论完成复核后才可进入报告；报告只组合接受或修改确认的内容，并支持编辑、预览和导出。
10. 更换输入后必须重新处理并得到新结果，不能复用固定演示数据。
11. 至少验证完整成功流程、常见失败与恢复、账号隔离、第二份不同输入和一次非开发用户试用迭代。
12. 交付可访问网页、完整源码、配置与部署说明以及一份共同小组报告。

任务网页还明确要求真实课堂视频完成完整流程；仅上传现成逐字稿不能作为视频处理能力的替代证明。
提交材料只有网页、源码和个人/小组报告三项，未要求答辩演练。

### 3.2 当前可信结论

两段内容不同的真实课程视频（计算机/人工智能、人文社科各一段）已经分别完成以下技术纵向链路：

```text
B2 私有对象上传 → 后端 HEAD 核验 → Worker 限时下载
→ FFmpeg 音频抽取 → Whisper 语音识别 → PostgreSQL 时间戳逐字稿
→ 英文/混合片段由本地 Ollama 逐句翻译（教师 SRT/VTT 可优先覆盖）
→ Ollama qwen3.5:4b 结构化分析 → 事实/判断/建议
→ 教师接受/修改/驳回 → Markdown/HTML/PDF 导出
```

浏览器还验证了“视频 + 教师提供 UTF-8 VTT”同时上传：Worker 仍从原视频生成 ASR 原文，
再按时间覆盖对齐教师译文。除此之外，Worker 已接通 loopback-only 的 Ollama 自动翻译 Provider；
教师译文存在时仍优先使用教师输入。自动路径已用真实 `qwen3.5:4b` 验证英文、混合文本和提示
注入式文本的逐句中文输出，但尚未完成一段真实英文课堂的浏览器全链路验收。

### 3.4 下一优先级

1. 补齐两段媒体来源 URL 与复用授权记录；
2. 使用一段真实英文或中英混合课堂完成自动翻译浏览器 E2E；
3. 真实课件证据写回、定位与展示；
4. 非开发教师浏览器独立试用及问题复测；
5. 干净环境部署复现与公开可访问地址。

## 4. 产品流程与交互

### 4.1 主流程

```text
创建课程/课堂
→ 对话说明复盘目标
→ Agent 追问并形成分析契约
→ 上传视频及可选辅助资料
→ 查看真实处理状态
→ 校订逐字稿和双语内容
→ 逐条核对证据与分析
→ 接受、修改确认或驳回
→ 全部复核后编辑、预览并导出报告
```

对话区负责明确需求和解释结果，工作区负责查看状态、证据与执行修改。二者共同服务同一任务，
不能做成互不相干的聊天页和数据页。

### 4.2 分析契约

教师确认后，系统保存一份任务级分析契约，至少包含分析范围、关注问题、事实/判断/建议的
判定要求、是否要求中英双语证据以及教师确认状态和版本。

若用户误选双语要求，页面必须解释失败原因，并允许关闭双语重试或补充 SRT/VTT 译文；
系统不得静默伪造译文。

### 4.3 证据结论

| 字段 | 含义 |
|---|---|
| `type` | `fact`、`judgment` 或 `suggestion` |
| `content` | 当前显示内容 |
| `evidence` | 时间范围、原文、课件页或画面引用 |
| `review_status` | `pending`、`accepted`、`modified` 或 `rejected` |
| `teacher_revision` | 教师改写内容与复核说明 |
| `trace_id` / 版本 | 回溯处理与模型运行 |

证据点击后必须回到对应视频时间、逐字稿、课件页或画面。事实只陈述可观察内容；判断说明
教学意义；建议必须回应前两者，不能跳过依据。

### 4.4 人工复核

工作台一次聚焦一条结论，清楚显示总数、当前位置和未完成数。操作分别为“接受并继续”、
“修改确认并继续”和“驳回并继续”。保存成功后自动进入下一条未复核内容并给出提示；最后一条
完成后显示“已全部审核完成”，不得循环回第一条。报告入口在所有结论复核前禁用。

### 4.5 UI 基线

当前界面基线为“雾境竹影”：霞鹜文楷与 Fraunces 字体、雾面玻璃、朦胧竹影、克制的
中性色与绿/黄/红状态色。正文和标签字号不低于 12px，面向年长教师时优先保证可读性。

- 页面使用 Reveal on Scroll、轻微视差和 Toast，但动画必须克制并支持减少动态效果；
- 组件透明度、模糊和背景纹理不能降低文本对比度；
- 同一语义只使用一套颜色；状态色不使用无意义渐变；
- 重要操作需具备按钮形态、键盘焦点和清晰禁用原因；
- 电脑端正常使用，手机端不得遮挡或横向溢出。

## 5. 成功标准与评分映射

一名未参与开发的教师无需查看代码或听讲解，能用新的非预置输入完成主流程，并知道系统
正在做什么、失败在哪里、下一步能做什么。最终报告不得包含待确认、已驳回或无证据内容。

| 部分 | 分值 | 本项目证据 |
|---|---:|---|
| 实际交付 | 60 | 用户价值、核心流程、真实实现与可用性 |
| 个人/小组报告 | 30 | 需求设计、技术范围、验证迭代与 AI 协作 |
| 个人贡献 | 10 | 每位成员实际完成、协作和证据 |

## 6. 总体架构与数据流

### 6.1 模块边界

| 模块 | 主要职责 | 不应承担 |
|---|---|---|
| `frontend/` | Next.js 页面、同源 BFF、上传、任务状态、证据工作台、报告交互 | 保存长期密钥、伪造任务进度 |
| `backend/` | FastAPI、身份与权限、业务状态、PostgreSQL、对象存储签名、内部服务接口 | 在数据库塞视频、绕过所有权校验 |
| `worker/` | 下载媒体、FFmpeg、Whisper、翻译/课件解析、逐字稿与证据索引 | 做开放式教学判断 |
| `agent/` | 基于已验证证据生成结构化分析，执行模型与 Skill，写回结论 | 读取无归属资源、脱离证据生成报告 |
| `tests/` | 契约、集成、前端、隐私与人工验收记录 | 用 Mock 代替真实链路结论 |

### 6.2 数据流

```text
浏览器 ──同源 BFF/JWT Cookie──> FastAPI ──> PostgreSQL
   │                                 │
   └────限时预签名 PUT/GET────────> 私有对象存储
                                     │
FastAPI <──服务令牌── Worker <───────┘
   │                   │
   │                   └──逐字稿/证据写回
   └──服务令牌── Agent ──结构化结论写回
```

Worker 与 Agent 独立轮询、独立服务令牌、独立租约。可并行的媒体预处理可以并行；证据门禁、
分析、教师复核与报告必须按顺序执行。

### 6.3 技术选型

- 前端：Next.js、React、TypeScript；
- 后端：Python 3.13、FastAPI、SQLAlchemy、Alembic；
- 数据库：PostgreSQL 17；
- 对象存储：S3 兼容接口，开发可用 MinIO，真实验收使用私有 Backblaze B2；
- 媒体：FFmpeg、Whisper；
- 本地模型：Ollama `qwen3.5:4b`；
- 报告：服务端生成 Markdown、HTML、PDF。

## 7. 状态、接口与数据约定

### 7.1 状态机

```text
uploaded → preprocess → transcribe → align → evidence → analyze → review → report
              └──────────── failure / retry / cancel ─────────────┘
```

页面只展示后端任务记录，不使用前端计时器伪造进度。每次状态改变写入任务事件并保留
`trace_id`；失败响应提供稳定错误码、用户可理解信息和可安全公开的追踪号。

### 7.2 核心实体

- 用户、课程、课堂；
- 资产（视频、课件、逐字稿、译文和导出文件）；
- 处理任务、阶段事件、租约与重试记录；
- 逐字稿及分段；
- 分析契约、证据结论、复核历史；
- 报告、导出记录、审计事件。

实体以 UUID 标识，时间使用带时区 ISO 8601，媒体时间使用非负毫秒。所有业务查询必须先验证
用户对课程/课堂/任务的归属，不能依赖前端隐藏资源。

### 7.3 关键业务 API

实际路径、字段与响应模型以 FastAPI OpenAPI 和 `backend/app/schemas/` 为准。稳定业务能力包括：

- `/auth/demo`、`/auth/login`、`/auth/me`；
- 课程与课堂创建、读取和更新；
- 上传预签名、资产完成核验、下载预签名和删除；
- 任务创建、查询、事件、重试和取消；
- 逐字稿读取与片段修改；
- 结论读取、复核与复核历史；
- 报告读取、保存、发起导出和下载三种格式；
- Worker/Agent 的任务领取、心跳、状态与结果写回内部接口。

外部接口使用教师 JWT；内部接口使用 Worker 或 Agent 专属服务令牌。二者不可共用，也不可由
浏览器持有。上传完成只能在后端 HEAD 校验大小、类型和对象存在性后确认。

### 7.4 变更规则

Schema、枚举、错误码或状态转换变化时，代码负责人先更新后端 Schema 和测试，同步前端
TypeScript 契约与 Worker/Agent 消费方，在 PR 中列出影响与迁移方式，并由至少一个受影响
模块负责人复核。

## 8. Agent、Skill、MCP 与 Harness

### 8.1 编排模式

本项目采用“显式状态机 + 有界工具调用 + 证据校验门禁”，不采用无限循环的自由 ReAct。
原因是教学分析必须可回溯、成本可控并在证据不足时失败关闭。

运行时先形成确定的 Skill 计划，再把本轮允许的 Skill、结论类型和证据 UUID 收紧为动态 JSON
Grammar。若完整契约校验失败，只允许一次同约束重新生成；若事实、判断或建议层缺失，则分别以
单一目标类型进行有界补全。补全结果仍须经过独立白名单、UUID、证据归属和专业规则校验，
不能把无效模型字段静默改写成“成功”。这是一种适合本项目的计划先行、有界修复模式，而不是
让模型在开放工具空间中无限试错。

```text
Perceive：读取分析契约、逐字稿、译文、课件证据和任务状态
Reason：按事实/判断/建议规则生成候选结论
Action：调用受限模型/Skill，校验并写回结论
Learn：只保存教师修改、复核历史和评测反馈，不在线修改模型参数
```

“Learn”在 M1 中指可审计反馈积累，不代表未经同意训练教师数据。

### 8.2 运行边界

- Agent 只读取当前任务已验证的证据版本；
- 双语契约要求译文但证据不完整时返回 `BILINGUAL_EVIDENCE_INCOMPLETE`，不得伪造；
- 引用必须落在已有逐字稿/媒体时间范围内；
- 逐字稿单独保存完整抽取音频时长，不能用最后一句结束时间截断播放器末尾静音；旧任务才回退
  到最后一句结束时间；
- 输出先通过 JSON Schema、枚举、证据范围和专业规则校验，再写回后端；
- 日志记录 Provider、模型、Prompt/Skill 版本、阶段、耗时、重试和 `trace_id`，不记录密钥或完整隐私原文；
- 只有接受或修改确认的结论进入报告。

### 8.3 Skill、MCP 与 Harness

Skill 用于封装教学分析规则，例如互动节奏和概念讲解检查；Skill 不能绕过证据校验。
模型 Provider 通过适配层替换，本地 Ollama 是当前真实实现。

MCP 适合未来接入已授权的课程平台、知识库或文件服务，但 M1 没有为了展示术语而强行引入；
未实际调用的 MCP 不得写成已实现。Harness 由任务状态机、租约、重试、日志、结构化校验、
自动化测试和人工复核共同组成，而不只是一个 Prompt。

## 9. 数据、隐私与安全

- 视频进入私有对象存储，数据库不保存二进制；对象键使用不可猜测 ID，不含姓名或邮箱。
- 浏览器只获得限时、限对象、限操作的预签名 URL；长期存储密钥只在后端和 Worker 环境中。
- JWT 使用短期 HttpOnly Cookie；Cookie、服务令牌、密码和预签名 URL 不得进入浏览器存储、日志、报告或 Git。
- B2 使用限制到项目 Bucket 的 Application Key，不使用网站登录密码或主密钥。
- 所有资源按用户、课程、课堂和任务归属；后端执行两账号隔离。
- 原始与派生对象按配置保留并清理；删除同时覆盖业务记录、对象和不含敏感值的审计状态。
- 公开仓库不提交课堂视频、学生信息和真实逐字稿；私密课堂默认本地处理。
- 错误与日志只提供可公开追踪号，不泄露内部路径、对象键、连接串或模型推理过程。

### 10.3 `.env` 原则

`.env` 被 Git 忽略，只在本机或部署平台填写。必须配置数据库、JWT、演示账号、Worker/Agent
独立服务令牌、对象存储和模型信息。真实值不得出现在本文、`.env.example`、Issue、PR、截图
或聊天中；没有 B2 权限的成员使用本地 MinIO，不共享个人网站密码。

### 10.4 基础设施与迁移

### 10.6 临时跨网络联调

完整本地链路运行后，入口负责人可执行：

```powershell
.\scripts\start-team-tunnel.ps1
```

Cloudflare Quick Tunnel 只用于短时组员联调，不是正式部署。负责人私聊发送随机 HTTPS 地址和
本次访问码；停止进程后立即失效。跨网络浏览器直传必须使用私有 B2，并把本次精确来源临时
加入 Bucket CORS，结束后移除。不得长期放行所有 `trycloudflare.com` 子域。

### 10.7 常见问题

| 现象 | 优先检查 |
|---|---|
| 前端提示后端不可用 | FastAPI 窗口、`BACKEND_URL`、`/health` |
| `/health` 成功但 `/health/ready` 失败 | PostgreSQL、密码、`DATABASE_URL`、Alembic |
| B2/MinIO CORS 错误 | 当前页面来源是否与 Bucket CORS 精确一致 |
| 上传成功但任务不继续 | Worker 是否启动、令牌与后端地址是否一致 |
| Agent 无法写回 | Agent 进程、专属令牌、证据和双语门禁 |
| 报告无法进入 | 是否仍有 `pending` 结论、浏览器会话是否过期 |
| `EADDRINUSE` | 是否已有本项目服务，避免重复启动 |

排错截图可保留页面状态和 `trace_id`，但必须遮住 Cookie、Authorization、密码、服务令牌、
Application Key、连接串和预签名 URL。

| 成员 3 | 身份、课程/课堂、任务、数据库、对象存储、报告后端 | 冻结跨模块 Schema 与权限 |

### 11.2 目录责任

- `frontend/`：成员 1 维护流程与基准，成员 2 维护证据工作台；
- `backend/`、`migrations/`：成员 3 主责；
- `worker/`、媒体样例规则：成员 4 主责；
- `agent/`、发布和运行时质量：成员 5 主责；
- `docs/`、`reports/`、最终验收：成员 1 统筹，但各成员对本人事实负责。

跨模块修改允许由阻塞处理者完成，但 PR 和报告必须把原实现、后续修复与最终验证分别归属，
不能按文件路径自动认定贡献。

### 11.3 四阶段研发路径

1. 判定背景与用户需求：形成用户、场景、困难、边界和成功标准；
2. 设计产品方案：形成流程、页面、交互、功能取舍和判定方式；
3. 确定技术路线并实现：形成架构、Schema、代码、状态、错误、权限和运行记录；
4. 真实场景验证迭代：使用非预置输入、失败场景和用户反馈修正产品。

四天集中开发只规定节奏，不改变上述依赖关系。M1 未闭环前，不投入 M2、M3 或知识图谱。

## 13. 发布门禁

- 网页可访问，源码、配置说明和三份主文档齐全；
- 真实核心链路由实际数据、模型、规则或工具驱动；
- 新输入产生对应新结果；
- 加载、成功、失败、重试和取消状态可理解；
- 身份、对象存储、日志和导出不泄露敏感信息；
- Python、前端测试、类型检查、生产构建和敏感文件扫描通过；
- 至少记录完整成功、常见失败与恢复、账号隔离和真实用户试用；
- 未实现能力明确标注，不把模拟冒充真实运行；
- 小组报告准确区分五位成员的计划、实际完成、协作修复和尝试。
