# UI Baseline v1：雾境竹影

> 确认人：成员 1（组长）  
> AI 协作：Codex 参与原型生成、代码迁移与自动检查；视觉判断、修改意见和最终采用决定由成员 1 完成。  
> 状态：2026-07-27 已冻结为成员 2 后续前端工作的第一版基准。

## 1. 适用范围

本基准覆盖产品首页、创建课程与课堂、说明复盘目标和确认分析契约。它定义视觉语言、基本信息层级和流程入口，不代表后端、媒体处理、证据分析或真实 Agent 已完成。

## 2. 设计语言

- 方向：雾境画廊；朦胧竹影投射在雾面玻璃上，融合东方意象、现代材质和克制的国际排版。
- 字体：中文使用霞鹜文楷，英文使用 Fraunces；正文不小于 15px，辅助文字不小于 13px，大型艺术标题除外。
- 材质：半透明玻璃、极细描边、柔和模糊、微噪点、低饱和竹青灰色板。
- 动效：Reveal on Scroll、滚动进度、轻量视差和状态切换；必须克制并尊重 `prefers-reduced-motion`。
- 可读性：教授用户优先，正文与标签不得因艺术效果牺牲清晰度；桌面和移动端均不得遮挡核心操作。

## 3. 实现位置

- `frontend/src/components/baseline/`：第一版流程与共享壳层。
- `frontend/src/app/globals.css`：共享设计令牌、响应式和动效。
- `frontend/public/assets/mist-bamboo-glass-v2.png`：已确认的竹影背景。
- `frontend/tests/ui-baseline.test.mjs`：字号、资产和 Mock 边界的轻量回归门禁。

未迁入临时原型的 QA 截图、旧背景 v1、旧 CSS 和浏览器缓存，避免污染仓库。

## 4. 成员 2 接入规则

1. 证据工作台组件继续放在 `src/components/evidence/`，不要复制一套独立色板或字体。
2. 在 `tasks/[taskId]` 中从“契约已确认”状态进入上传与证据工作台；真实状态必须来自后端，不使用计时器伪造。
3. 可以优化组件与响应式，但若改变字体、字号下限、主色、背景或整体布局，PR 必须附前后截图并由成员 1 确认。
4. 所有 Mock/TODO 状态保持显著标注；接通真实接口后再删除对应标识。

```powershell
npm ci
npm test

npm run build
```

视觉验收还需保存桌面与移动端截图，并人工确认导航、表单错误、分析契约、动效降级和无障碍字号。
