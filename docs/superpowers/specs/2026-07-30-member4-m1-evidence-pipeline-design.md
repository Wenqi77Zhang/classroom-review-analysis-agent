## 4. 方案比较

### 方案 A：成员 4 先完成 Worker 内部能力，再按冻结契约联调（采用）

成员 4 先实现阶段处理、内存中的证据索引、专业规则和确定性测试；同时提交后端契约草案。
成员 3 冻结并实现后端能力后，成员 4 再连接真实持久化、handoff 和重试。

优点：

- 不越过模块责任边界。
- 后端契约变化不会迫使 Worker 反复重写。
- 模型未确认时，其他工作仍可验证。

代价：

- P0 的完整联调依赖成员 3 及时完成契约。
- 在接口冻结前，只能证明 Worker 内部输出，不能声称端到端完成。

### 方案 B：成员 4 同时修改 Worker、后端和 Agent 运行器（不采用）

看似更快，但责任归属、权限、迁移和审计无法由单个成员确认，且容易与成员 3、5 的分支冲突。

### 方案 C：仅输出本地 JSON，不做真实系统交接（不采用）

适合临时演示，但不能证明账号隔离、重启恢复、任务状态或成员 2/5 的真实读取，不满足 M1。

## 6. 常驻 Worker

### 6.1 M1 单 Worker 轮询

`run_forever()` 重复调用现有单次领取逻辑：

- 无任务响应属于正常空闲，等待 `WORKER_POLL_INTERVAL_SECONDS` 后继续。
- 完成任务后立即尝试领取下一项。
- 可恢复 HTTP 错误使用有上限的基础退避，鉴权错误停止进程。
- SIGINT/SIGTERM 后不再领取新任务，并在安全检查点停止当前处理。
- 停止或 heartbeat 失败后禁止写 transcript、证据或状态。

等待函数和时钟可注入，测试不得真实睡眠。高级抖动、独立指标端口和完整容器归 P1。

### 6.2 租约限制

现有 heartbeat 能降低过期概率，但没有 `lease_id` fencing 时不能证明多 Worker 安全。

- 阶段一只支持一个 Worker 实例。
- 成员 4 提交 fencing 契约需求和旧租约拒写测试案例。
- 成员 3 实现并冻结 `lease_id` 后，成员 4 再启用多 Worker 相关测试。
- 在此之前部署文档明确禁止扩容到多个 Worker。

## 7. 可审计重试

禁止“数据库仍显示后段阶段，却在后台偷偷重跑 FFmpeg/ASR”。

M1 推荐采用“显式回到最早受影响阶段”：

- 任何 `transcribe` 之后且依赖逐字稿的阶段失败，重试时显式回到 `transcribe / queued`。
- 后端追加包含原失败阶段和重启阶段的审计事件。
- Worker 被重新领取后按正常事件顺序执行 transcribe、translate、parse_courseware 和
  build_evidence_index。
- 交接到 `analyze` 后，Worker 不再允许覆盖该任务的 transcript 或证据。

当前后端禁止阶段倒退，因此这只是提交给成员 3 的冻结建议。成员 3 确认前，成员 4 不实现
后段真实重试，也不使用隐藏重算方案。若成员 3 最终选择“持久化阶段产物并直接读取”，
成员 4 按冻结接口改为读取，不自行混用两种策略。

## 8. 翻译

### 8.1 TranslationAdapter

适配器接收原文批次和明确语言方向，返回与输入等长的译文及模型版本。适配器不访问数据库，
阶段层负责超时、停止检查、批次长度和 Schema 校验。

- `FakeTranslationAdapter`：只用于自动化测试，输出明确标识为测试数据的确定性译文。
- `LocalTranslationAdapter`：模型经人工确认后实现。

翻译继续使用现有 `InternalTranscriptWrite` 整批写回，不新增翻译后端接口。

### 8.2 语言与编辑边界

- 中文：保留原文，不生成多余译文。
- 英文：保留英文原文，生成逐句中文译文。
- 中英混合：保留完整原文，生成与该原句一一对应的中文译文。
- 无法支持的语言：稳定失败，不伪装为英文。

译文不能修改 `text`、时间戳或说话人。任务交给 `analyze` 后，Worker 不再领取或覆盖；
教师编辑继续使用已有逐字稿接口。

### 8.3 模型人工核验门禁

候选模型的 revision、许可证、权重大小、运行内存和使用限制只作为待核验材料。组长确认前：

- 不下载权重。
- 不添加真实模型依赖。
- 不提交模型缓存。
- 不把测试替身结果写成真实翻译。

组长确认后，代码固定模型 ID 和 revision，并在真实运行前再次核对官方模型卡、许可证和
实际下载文件。

## 9. PDF/PPTX 课件解析

P0 只实现文字和一基页码：

- PDF：逐页提取文字并保留页码。
- PPTX：逐幻灯片提取文本框、表格和备注中的可见文字，幻灯片序号作为页码。
- 加密、损坏、超页数、异常解压比例或不支持的文件稳定失败。
- 无文字页仍保留页码，但不伪造页面内容。
- 无课件任务明确记录“无课件”，不伪造课件证据。

课件页面 PNG、LibreOffice/Poppler 渲染、派生资源上传和页面缩略图属于 P1。P0 证据使用
`asset_id + page_no` 回到原课件，符合冻结 `EvidenceReference` 对课件定位的最低要求。

测试使用运行时生成的小型合成 PDF/PPTX；真实验收样例必须记录来源、许可和访问日期。
若样例不是视频配套课件，必须明确写成解析能力样例。

## 10. 证据索引

### 10.1 成员 4 输出

`EvidenceIndexDraft` 中每项包含：

- 由任务、来源、定位和内容摘要确定性生成的 ID；
- 来源 asset ID 和可选 transcript segment ID；
- 冻结 `EvidenceReference`；
- 必要原文、可选译文；
- 仅含处理版本和领域标签的非敏感 metadata。

来源定位：

- 视频/逐字稿：`start_ms + end_ms`；
- 课件：`asset_id + page_no`；
- 画面：只有真实时间或图像引用存在时才生成。

任何缺少合法定位、跨任务引用、时间越界或页码非法的条目在 Worker 内部先拒绝。

### 10.2 提交给成员 3 的持久化要求

证据写入必须满足：

- 只有持有有效租约的 Worker 能在 handoff 前写入。
- handoff 后禁止 Worker 替换证据。
- 每次重试生成新版本或追加明确审计事件。
- Agent 结论已引用的证据不能静默删除。
- 整批先校验后提交，失败不留下半批结果。
- 后端依据任务填写 owner，Worker 不能自报归属。
- 教师读取和 Agent 读取均按 `owner_id + task_id` 隔离。

具体表、迁移和端点由成员 3 设计实现。成员 4 只提供请求/响应草案和客户端验收用例。

## 12. 专业 Skill 与专业证据门禁

### 12.1 不修改的内容

- `agent/skills/common.py`
- 通用证据检索
- 通用 `EvidenceReference` Schema
- Agent 协调器
- Agent 常驻运行器

### 12.2 计算机/AI

- 区分概念定义、算法步骤、代码/公式讲解、演示结果和教学建议。
- 声称代码执行、界面操作或模型输出时，必须引用真实视频/画面或课件页。
- 仅出现技术术语不能推断演示成功、概念准确或学生掌握。
- 不推测教师水平、学生能力或意图。

### 12.3 人文社科

- 区分原文事实、文本解释、论证结构、价值判断和教学建议。
- 解释观点、修辞或论证关系必须引用课堂原文或课件页。
- 不把模型常识当成课堂证据。
- 不推测立场、动机、情绪或身份。

### 12.4 专业 evidence gate

专业附加校验只检查专业主张与证据类型是否匹配：

- 无时间、原文或课件页的专业结论拒绝。
- 代码运行/画面操作主张缺少视频、画面或课件证据时拒绝。
- 人文解释缺少原文或课件证据时拒绝。
- 双语要求范围内缺少英文原文或逐句译文时拒绝。

成员 4 提供规则函数和正反例，成员 5 负责接入通用协调器并审核没有削弱通用门禁。

## 15. 安全与 Git 提交边界

不得提交：

- 原始视频、完整逐字稿、课件原件和页面图像；
- 模型权重和模型缓存；
- `.env`、服务令牌、账号、Cookie 或对象存储密钥；

仓库只记录公开来源、许可依据、访问日期、文件摘要、处理参数、不可逆结果摘要、稳定错误码
和真实测试结果。
