# 产品方案

> 版本：Day 1 交互规格 + UI Baseline v1
>
> 负责人：成员 1；协作复核：成员 2、成员 3
>
> 当前状态：UI Baseline v1 已迁入 Next.js 并通过构建，尚未连接真实服务或进行目标用户试用；不得把 Mock 行为描述为已实现核心功能。

## 1. 产品定位

面向需要复盘一节公开课的高校教师，把长视频、逐字稿和课件转化为“可定位证据—可人工修改—可确认导出”的教学分析。产品不提供脱离证据的泛化评价，也不替学校自动给教师打分。

## 2. M1 核心场景

教师完成一节课后，希望判断“哪些片段值得复盘、系统依据了什么、下一次可以怎样改”。教师用自然语言说明目标，Agent 通过必要追问形成分析契约；系统处理真实课堂资料后，教师在工作区核对证据、修改结论，并导出只包含已确认内容的报告。

## 3. 核心流程

1. 创建课程与课堂。
2. 通过对话说明复盘目标。
3. Agent 追问并形成分析契约。
4. 上传视频、课件或逐字稿。
5. 查看真实处理状态。
6. 在证据工作台核对逐字稿、视频、课件和分析。
7. 接受、修改或驳回结论。
8. 编辑、预览和导出仅包含已复核内容的报告。

任何步骤失败时都停留在可恢复状态，保留已完成数据并提供重试或返回入口；不得用固定进度、固定结果或预置逐字稿冒充真实处理。

## 4. 对话区与工作区职责

| 区域 | 负责什么 | 不负责什么 |
|---|---|---|
| 对话区 | 收集复盘目标、补充信息、解释 Agent 追问、展示分析契约摘要和下一步 | 不承载逐条证据核对和长文本编辑 |
| 工作区 | 上传与进度、播放器、逐字稿、证据、结论复核、报告编辑预览 | 不重复询问已经在对话中确认的目标 |

对话中的目标、范围或条件发生修改时，工作区同步显示“契约已变更，需重新确认”；未经教师再次确认不得开始新的分析。

## 5. 分析契约

Agent 完成必要追问后，页面以可编辑摘要展示：

- 分析对象：整节课或指定时间范围。
- 复盘目标：教师想回答的教学问题。
- 关注维度：例如内容组织、讲解清晰度、提问与等待时间、课堂节奏。
- 证据条件：允许使用视频时间、逐字稿、课件页或画面，不接受无证据判断。
- 输出要求：区分事实、判断和建议；英文或中英混合课堂保留英文原文和逐句中文译文。
- 隐私确认：教师确认资料来源与处理权限。

教师可选择“返回修改”或“确认并开始处理”。确认动作写入任务记录；按钮连续点击不得创建重复任务。

## 6. 页面与关键交互

| 页面 | 成员 1 的交互目标 | 关键状态 |
|---|---|---|
| 首页/演示入口 | 一句话说明用户、问题和产出；进入真实核心任务 | 默认、服务不可用 |
| 登录 | 进入本人数据空间；演示账号与正式账号有明确提示 | 输入错误、加载、成功 |
| 课程与课堂 | 创建课程和单节课堂，进入复盘任务 | 空状态、校验错误、创建成功 |
| 对话与任务创建 | 输入目标、回答追问、修改并确认分析契约 | 等待回复、需补充、待确认、已确认 |
| 上传与任务看板 | 选择视频/课件/逐字稿，显示真实上传和处理状态 | 校验失败、上传中、处理阶段、失败可重试 |
| 证据工作台 | 由成员 2 实现证据联动；成员 1 保证流程入口和返回路径 | 加载、无结果、待复核、已复核 |
| 报告编辑/预览 | 只组合 accepted/modified 内容，支持编辑、预览、导出 | 未完成复核、可编辑、导出中、导出失败 |

## 7. 高价值交互

- 分析契约：处理前确认分析范围、指标、证据条件和隐私模式。
- 证据工作台：播放器、逐字稿、课件与分析卡片联动。
- 证据账本：记录模型、Prompt、Skill、证据和教师修改版本。
- 证据门禁：无证据、待确认和已驳回内容不能进入报告。
- 可恢复任务：失败状态说明失败环节、保留已完成步骤，并提供安全重试。

## 8. 上传与任务状态

- 上传前校验文件类型、大小和必需资料，但不在前端保存长期对象存储密钥。
- 上传进度来自真实传输事件；处理进度来自后端任务状态，二者不得混用。
- 页面至少显示：上传、音频抽取、分段、语音识别、翻译、证据索引、分析。
- 失败提示包含失败环节、可否重试和下一步；不得暴露堆栈、密钥、签名 URL 或内部路径。
- 更换视频创建新的资源和处理任务，不覆盖旧任务或沿用旧分析。

## 9. 首轮真实试用成功判断

- 用户无需开发者解释即可创建课堂并发起任务。
- 用户能说清 Agent 为什么追问，并能修改后确认分析契约。
- 用户能区分上传进度与后台处理阶段。
- 用户能从一条结论回到对应证据，并完成接受、修改或驳回。
- 用户能判断为什么某些内容没有进入报告。
- 记录一个完整成功流程和一个常见失败场景；发现问题后修改产品，并用同一任务复测。

具体步骤与记录字段见 `tests/manual/usability-record.md`。

- 先实现首页、课程/课堂创建、对话追问、分析契约、上传入口和任务看板的可操作流程。
- 以冻结接口类型为边界；后端尚未接通的地方必须保留明确 TODO 或“服务尚未接通”状态。

成员 1 已确认“雾境竹影”为第一版视觉基准。其设计语言、字号下限、资产位置和成员 2 接入规则以 `ui-baseline-v1.md` 为事实源。当前可运行范围为首页、课堂创建、复盘目标输入、分析契约和人工状态预览；这些页面明确标为 Mock，上传、真实处理、证据联动、人工复核和报告导出仍按原责任继续实现。

## 12. Day 1 上传入口实现状态

成员 1 已完成分析契约后的资料选择入口：

- 支持课堂视频、课件和逐字稿的本地选择与拖放。
- 校验扩展名、大小和重复文件；课堂视频作为 M1 真实处理链路门禁。
- 明确提示已有逐字稿不能替代视频生成时间戳证据。
- 文件仅保留在当前浏览器页面，不读取内容、不发送、不持久保存。
- 因成员 3 的预签名上传接口和 Schema 尚未冻结，真实上传按钮保持禁用并显示“上传服务尚未接通”；没有模拟进度或伪造对象地址。

待成员 3 完成接口后，成员 1 与成员 2 应按 `interface-contracts.md` 接入预签名请求、对象直传、上传确认、真实进度和失败重试。
