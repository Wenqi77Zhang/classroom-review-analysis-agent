# 技术架构

## 模块

- `frontend/`：Next.js/TypeScript 页面与证据工作台。
- `backend/`：FastAPI、PostgreSQL、认证、权限、对象地址和业务 API。
- `worker/`：对象读取、FFmpeg、ASR、翻译、课件解析、证据索引和重试。
- `agent/`：分析契约、模型路由、Skill、证据门禁、报告组合和 Trace。

## 数据流

浏览器预签名上传 → 对象存储 → 数据库登记任务 → Worker 生成逐字稿/译文/证据索引 → Agent 生成结构化分析 → 教师人工复核 → 已确认内容进入报告。

这是里程碑 M1 的目标数据流，不是当前完成声明。截至 `main@1e52c9c`，链路已经
到达“数据库登记任务”；Worker 从 B2 取得对象并消费任务正在其他对话实现，
之后的真实证据、Agent、复核和报告仍待集成。

## M1 已确认基础设施

- 对象存储采用 Backblaze B2 私有 Bucket，通过 S3 兼容 API 接入；代码必须依赖统一 `ObjectStorageProvider` 接口，不把 B2 专用逻辑散落到业务代码中。
- 成员 3 的后端使用受限应用密钥生成限对象、限操作、限时的预签名上传或读取 URL；浏览器不接触长期密钥，默认签名有效期为 15 分钟。
- 目标设计要求成员 4 的 Worker 通过受控存储边界从 B2 读取原始视频，并回写逐字稿、
  课件解析结果或证据索引。该 B2 读取集成尚未合并验收。
- Bucket 保持私有，按 `用户/课程/课堂/任务` 组织对象键；M1 仅使用具有明确来源和许可记录的公开课演示资料。
- 默认保留期为 7 天。删除课堂或到期清理时，同时删除原始对象、派生对象和数据库中的关联记录；实际生命周期规则与删除测试必须留存证据。
- 数据库继续只保存对象键、归属、版本、校验值、大小、媒体类型和处理状态，不保存视频二进制，也不保存可长期复用的签名 URL。

## 关键边界

- Worker 回答“怎样把输入加工成证据”。
- Agent 回答“怎样基于证据形成教学分析”。
- 后端持久化归属、状态和版本。
- 前端不持有长期对象存储密钥。
- Backblaze B2 是 M1 的默认实现，不是不可替换的业务依赖；替换供应商只能改 Provider 配置或适配器。
